# Frontend подготовка

Тренажёр подготовки к собеседованию Vue-разработчика: темы по направлениям и уровням, тесты с разбором ошибок, прогресс сохраняется.

## 1. Назначение

- **19 направлений**: JavaScript, TypeScript, Vue 3 и Composition API, Nuxt, React, Next.js, Redux, MobX, Keycloak, принципы и паттерны, архитектура фронтенда, CSS, HTML и доступность, UX/UI, браузер и сеть, тестирование и инструменты, Git, AI для разработчика, алгоритмы.
- **3 уровня** в каждом: Junior — база, на которую нужно отвечать уверенно; Middle — как всё устроено внутри; Senior — архитектура и решения.
- **4 темы на уровень** (администратор может добавить до 20) с примерами кода, схемами и блоком «Как сказать на собеседовании».
- **Тест из 12 вопросов** (теория и практика) в конце уровня: варианты перемешиваются, после проверки — объяснения и ссылка на тему с ответом.
- **Прогресс** (просмотренные темы, лучший и последний результат теста, где остановились) хранится в браузере. После входа через Google или по почте с паролем он синхронизируется между устройствами через Firebase; без входа его можно выгрузить в JSON и загрузить на другом устройстве.

Пакеты сверх обязательного стека:

- **`unplugin-vue-components` + `@primevue/auto-import-resolver`** — автоимпорт компонентов PrimeVue (рекомендованный PrimeVue способ: в бандл попадают только используемые компоненты). Свои компоненты импортируются явно, чтобы границы FSD были видны в коде.
  Автоимпортируемые компоненты не видны сканеру зависимостей Vite, поэтому используемые компоненты PrimeVue перечислены в `optimizeDeps.include` в [vite.config.ts](vite.config.ts). Подключили новый компонент — добавьте его в этот список.
- **`jiti`** — нужен ESLint для чтения конфига на TypeScript (`eslint.config.ts`).
- **`@vitest/eslint-plugin`** — правила ESLint для тестов (например, запрет `it.only`).

Почему границы FSD проверяются правилом `no-restricted-imports`, а не `eslint-plugin-boundaries` или `steiger`: встроенного правила ESLint достаточно для трёх нужных проверок (импорт только из нижележащих слоёв, запрет кросс-импорта слайсов одного слоя, запрет глубоких импортов в обход `index.ts`). Ему не нужен резолвер импортов, оно работает в редакторе и в lint-staged и не добавляет зависимостей. Правила генерируются в [eslint.config.ts](eslint.config.ts) по списку слоёв.

## 3. Требования

- **Node.js** `^22.18.0` или `>=24.12.0` (версия для `nvm` — в [.nvmrc](.nvmrc));
- **pnpm** 11 (версия закреплена в поле `packageManager` в `package.json`). Проще всего включить его через Corepack: `corepack enable`. Corepack сам скачает нужную версию.

Почему pnpm: установка быстрее и занимает меньше места благодаря общему хранилищу пакетов. Строгий `node_modules` не даёт импортировать пакеты, которых нет в `package.json`. Скрипты зависимостей по умолчанию не запускаются, разрешённые перечислены в `allowBuilds` в [pnpm-workspace.yaml](pnpm-workspace.yaml). Не используйте `npm install` или `yarn`: lock-файл проекта — `pnpm-lock.yaml`.

## 6. Архитектура: Feature-Sliced Design

```
src/
  app/                    # инициализация: провайдеры (Pinia, Router, VueQuery, PrimeVue), SEO (seo/), глобальные стили
  pages/
    home/                 # список направлений, общий прогресс, «Продолжить»
    level/                # уровень: шаги-темы, тема, тест
    admin/                # админка: редактор контента (темы и тесты), отзывы пользователей и статистика
    not-found/
  widgets/
    app-header/
    track-grid/           # карточки направлений со статусом уровней
  features/
    run-quiz/             # тест: сессия, проверка, подсчёт результата
    manage-progress/      # экспорт, импорт и сброс прогресса
    sync-progress/        # синхронизация прогресса через Firebase
    edit-content/         # редактор контента: блоки тем, вопросы теста, права администратора, сохранение правок
    send-feedback/        # замечания пользователей: форма (ленивый чанк), кнопка у выделения, ссылки в теме, тесте и подвале
    review-feedback/      # отзывы в админке: фильтр по статусу, статус, заметка, удаление, переход в редактор
    view-analytics/       # отчёт Google Analytics в админке: графики, SEO, источники
    analytics-consent/    # баннер согласия на статистику, включение Google Analytics
    toggle-theme/
  entities/
    track/                # типы, индекс направлений, ленивая загрузка уровней, правки из админки, валидатор, очистка HTML, контент (data/)
    progress/             # стор прогресса с сохранением в localStorage, слияние для синхронизации
    session/              # вход через Google или по почте, общий для синхронизации и редактора; анонимный вход только для замечаний
    feedback/             # замечания: типы, проверка, запись и чтение в базе, список «Мои замечания»
  shared/                 # api, config, lib (загрузчик Firebase, скачивание файлов), styles (в т. ч. _content.sass для HTML тем)
build/
  prerender.ts            # плагин Vite: статический HTML страниц, sitemap.xml, robots.txt, 404.html
```

**Правила импортов** (проверяются ESLint):

1. Слой импортирует только из слоёв ниже: `app → pages → widgets → features → entities → shared`.
2. Слайсы одного слоя не импортируют друг друга (`features/a` не знает о `features/b`).
3. Наружу слайс отдаёт код только через `index.ts`: `import { fetchLevel } from '@/entities/track'`. В `shared` публичный API есть у каждого сегмента: `@/shared/config`, `@/shared/lib`.
4. Внутри слайса используются относительные импорты.

Алиасы: один алиас `@` → `src/`.

## 7. Стили

- **Почему Sass в indented-синтаксисе.** Он короче SCSS (без `{}` и `;`), отступы делают вложенность наглядной, а модульная система `@use` / `@forward` даёт пространства имён без глобальных переменных. SCSS-файлы и `@import` в проекте запрещены.
- **Где токены.** В [src/shared/styles/](src/shared/styles/): `_tokens.sass` (отступы, радиусы, брейкпоинты, шрифты), `_mixins.sass` (`media`, `container` и др.), `_index.sass` (`@forward` обоих файлов).
- **Стили компонентов — в отдельных файлах.** Рядом с каждым компонентом лежит `.sass` с тем же именем (`QuizRunner.vue` → `QuizRunner.sass`). Блок `<style>` в SFC только подключает его:

  ```vue
  <style lang="sass" scoped>
  @use './QuizRunner'
  </style>
  ```

  `scoped` работает и для подключённых правил: Vue проставляет атрибуты `data-v-*` уже скомпилированному CSS блока.
- **Как подключать токены.** Файл стилей компонента первой строкой подключает токены и миксины под пространством имён `ds`:

  ```sass
  @use "@/shared/styles" as ds

  .quiz-runner
    padding: ds.$space-4
    color: var(--p-text-color)

    +ds.media(md)
      padding: ds.$space-6
  ```

  `vite.config.ts` через `additionalData` добавляет этот `@use` автоматически, но только в сам блок `<style lang="sass">`. В файлы, подключённые через `@use`, он не попадает, поэтому в `.sass` компонента его пишут явно.

- **Цвета** берутся только из CSS-переменных PrimeVue (`var(--p-primary-color)`, `var(--p-content-background)` и т.д.), поэтому тёмная тема работает без дополнительного кода. Тёмный режим включает класс `.app-dark` на `<html>`. Пользователь выбирает режим в шапке: светлая, тёмная или «как в системе» (по умолчанию). В системном режиме тема меняется вслед за настройкой ОС, в том числе без перезагрузки страницы. Чтобы при загрузке не мелькала светлая тема, класс ставит встроенный скрипт в `index.html` ещё до первой отрисовки.
- **Именование классов** — БЭМ плюс `scoped`.
- **Vite 8** всегда использует современный Sass-компилятор, поэтому опция `api: 'modern-compiler'` в нём удалена и в конфиге не нужна.

## 8. Контент и прогресс

**Контент** лежит в `src/entities/track/data/`:

- `tracks.json` и `tracks-extra.json` — индекс направлений: названия, описания уровней, заголовки тем, число вопросов. Попадает в основной бандл.
- `levels/<направление>-<уровень>.json` — темы и тест уровня, например `vue-middle.json`. Каждый файл — отдельный чанк, грузится при открытии уровня (`import.meta.glob`).

HTML тем доверенный и использует только классы из `src/shared/styles/_content.sass`: `note`, `note warn`, `say`, `pre.code` (комментарии в `span.c`), `code-label`, `table-wrap`, `figure`/`flow`/`step`/`arrow`, `boxes`/`box`. Новые теги, атрибуты и классы добавляйте и в белый список [sanitize.ts](src/entities/track/lib/sanitize.ts): иначе тест `sanitize.spec.ts` упадёт, а правки из админки с ними будут очищаться.

Вопрос теста:

```ts
{ topic: 0, type: 'theory' | 'practice', question: '…', code?: '…', options: ['…', '…', '…', '…'], answer: 1, explanation: '…' }
```

`topic` — номер темы уровня, где объясняется ответ; `answer` — индекс верного варианта.

**Как добавить направление:** положите три файла `levels/<id>-junior|middle|senior.json` и добавьте запись в `tracks-extra.json`. Заголовки тем в индексе должны совпадать с заголовками в файлах уровней — это и форму вопросов проверяет тест [content.spec.ts](src/entities/track/api/content.spec.ts).

**Прогресс** хранит `useProgressStore` из `entities/progress` в `localStorage` под ключом `vue-interview-prep:progress`:

```ts
{ version: 1, levels: { 'vue-middle': { seenTopics: [0, 1], bestScore: 83, lastScore: 75, attempts: 2, passedAt: '…' } }, lastVisited: { levelId: 'vue-middle', step: 'quiz' } }
```

Тема отмечается просмотренной, когда она показана (после загрузки уровня). Прочитанные темы считаются только в пределах числа тем уровня (`seenCount`, `topicsPercent`): номера удалённых тем в прогрессе остаются, но не дают больше 100 %. Уровень считается пройденным при результате теста от 80 %. Повреждённые записи при чтении отбрасываются. Если меняете формат — поднимите `version` и добавьте миграцию. На главной есть экспорт в JSON, импорт и сброс.

### Синхронизация между устройствами

Кнопка с облаком в шапке открывает вход: через Google или по почте с паролем (там же регистрация и сброс пароля письмом). При регистрации по почте приходит письмо со ссылкой: пока почта не подтверждена, прогресс в аккаунт не сохраняется, а значок аккаунта в шапке оранжевый и объясняет почему. Это же проверяют правила базы (`auth.token.email_verified`). После входа прогресс хранится в Firebase Realtime Database по пути `interviewPrep/users/<uid>/progress` и обновляется на всех устройствах в реальном времени; `localStorage` остаётся локальной копией, так что приложение работает и без сети. При первом входе прогресс устройства объединяется с прогрессом аккаунта: темы складываются, берётся лучший результат и больше попыток. Дальше источник правды — база: сброс на одном устройстве сбрасывает прогресс везде. SDK Firebase загружается отдельным чанком и только у тех, кто включил синхронизацию.

У приложения свой Firebase-проект. Настройка:

1. **Authentication → Sign-in method** — включите **Google**, **Email/Password** и **Anonymous** (анонимный вход нужен только для отправки замечаний, см. «Обратная связь»).
2. **Authentication → Settings → Authorized domains** — добавьте `leaderdsn.github.io` (`localhost` там уже есть).
3. **Realtime Database → Rules** — вставьте содержимое [database.rules.json](database.rules.json) и опубликуйте. Каждому пользователю доступен только его прогресс, правки из редактора контента читают все, а пишут только администраторы. Все данные лежат под узлом `interviewPrep`.
4. Для локального запуска создайте `.env.local` по образцу [.env.example](.env.example).
5. Для сайта на GitHub Pages добавьте те же значения в **Settings → Secrets and variables → Actions** репозитория
   (`VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_DATABASE_URL`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`) и перезапустите workflow **Deploy**.

Ключи веб-конфига Firebase публичные по своей природе; доступ к данным ограничивают правила базы.

### Редактор контента

Страница `/admin` (ссылка «Редактор» внизу сайта), вкладка «Контент». Администратор входит через Google или по почте, выбирает направление и уровень, а затем переключателем «Темы | Тест» — что править. Черновики обеих частей живут в памяти, пока открыт уровень: переключение «Темы | Тест», между темами и на вкладку «Статистика» их не сбрасывает. При смене уровня несохранённые правки пропадают — об этом предупреждает плашка над редактором, а при закрытии вкладки браузер переспрашивает. Редактор показывает, есть ли у уровня правка в базе, когда и кем она сохранена.

**Тест.** Вопросы: текст, тип (теория или практика), тема, где объясняется ответ, необязательный код, четыре варианта, правильный ответ и пояснение. Вопросы можно добавлять, удалять и переставлять. Перед сохранением тест проверяется тем же валидатором ([validate.ts](src/entities/track/lib/validate.ts)), что и файлы уровней в `content.spec.ts`.

**Темы.** Выбирается тема уровня, правится её заголовок и текст. Под выбором темы — «Новая тема» (тема с заголовком «Новая тема» и пустым абзацем добавляется в конец и выбирается), «выше» / «ниже» и «Удалить тему» с подтверждением на месте. Тем в уровне от 1 до 20 (`MAX_TOPICS`), последнюю удалить нельзя; в списке тем новые и изменённые отмечены.

**Темы и номера тем в вопросах.** Вопрос ссылается на тему номером (`question.topic`), поэтому темы и тест — один черновик уровня ([levelDraft.ts](src/features/edit-content/model/levelDraft.ts), операции — [structure.ts](src/features/edit-content/model/structure.ts)). У каждой темы черновика есть `origin` — её номер среди опубликованных тем (у новой — `null`):

- добавление и перестановка темы сразу переписывают номера тем в вопросах — вопросы следуют за своими темами;
- у вопросов удалённой темы тема сбрасывается: в тесте ошибка «Вопрос N: тема удалена — выберите другую», и сохранить нельзя, пока тема не выбрана;
- «Отменить изменения» у тем возвращает и темы, и номера тем в вопросах (в том числе вопросам удалённых тем);
- тест проверяется по числу тем черновика — столько тем увидят пользователи после сохранения.

Если структура тем изменилась (число, порядок, новые или удалённые темы), «Сохранить для всех» и в «Темах», и в «Тесте» записывает **обе части одним `update`**: в базе не может оказаться теста, ссылающегося на темы по старым номерам. Если правились только заголовки и блоки, сохраняется только своя часть.

Текст темы разложен на блоки ([blocks.ts](src/features/edit-content/model/blocks.ts)):

| Блок | HTML |
|---|---|
| Подзаголовок, Абзац | `<h3>`, `<p>` |
| Список | `<ul>` / `<ol>` с пунктами |
| Код | необязательная подпись `div.code-label` + `pre.code` |
| Заметка, Ловушка | `div.note`, `div.note.warn` |
| Как сказать на собеседовании | `div.say`; подпись `span.eyebrow` добавляется сама |
| Таблица | `div.table-wrap` с одной строкой заголовков и строками данных |
| HTML | всё остальное как есть: схемы `figure`/`flow`, карточки `boxes`, таблицы с `colspan` |

У каждого блока — форма, предпросмотр в стилях темы, кнопки «выше», «ниже», «дублировать», «удалить»; «Добавить блок» есть между блоками и в конце. Текстовые поля принимают строчную разметку `<b>`, `<code>`, `<i>`, `<a href target rel>`; кнопки «b» и «code» оборачивают выделенный текст. Код пишется обычным текстом: при сохранении он экранируется, а комментарии `//` и `#` (в начале строки или после пробела; после `#` — пробел, `#`, `!` или конец строки) оборачиваются в `span.c`.

Разбор и сборка без правок дают ровно исходный HTML: блок хранит свой исходный HTML и пробелы вокруг и собирается заново только после изменения. Это проверяет тест на всех темах всех уровней (`blocks.spec.ts`), поэтому в скачанном JSON меняются только отредактированные блоки.

**Хранение.** Правка лежит в базе по пути `interviewPrep/content/<уровень>`:

```ts
{ quiz?: QuizQuestion[], topics?: { title, html }[], updatedAt: '…', updatedBy: 'admin@…' }
```

Части сохраняются и удаляются независимо (`update` отдельных полей): сохранение тем не трогает тест и наоборот, кроме изменения структуры тем (см. выше). Старые записи только с `quiz` читаются как раньше.

Как правка применяется у пользователей (`resolveOverride` в [overrides.ts](src/entities/track/api/overrides.ts); те же правила показывают в редакторе, что сейчас видят пользователи):

1. Темы правки применяются, если их от 1 до 20 и у каждой после очистки HTML есть заголовок и текст. Число тем может отличаться от сборки.
2. Тест правки проверяется по фактическому числу тем (из правки, если она применена, иначе из сборки).
3. Если тест правки не подходит или его нет, берётся тест из сборки — но только если он подходит к фактическим темам. Иначе правка тем тоже отбрасывается и пользователи видят уровень из сборки целиком.

О пропущенной части пишется предупреждение в консоль, а редактор показывает плашку «правка некорректна».

**Очистка HTML.** HTML тем из базы проходит белый список [sanitize.ts](src/entities/track/lib/sanitize.ts) (DOMParser) — и при сохранении, и у пользователей перед показом. Разрешены только теги, атрибуты и классы, которые встречаются во встроенном контенте: `class` из `_content.sass`, `href` (http, https, относительные и якоря), `target`, `rel`, `colspan`, `aria-hidden` и `style="margin:0"` у `figure`. Скрипты, `iframe`, `img`, обработчики `on*` и `javascript:`-ссылки удаляются. Предпросмотр блока показывает уже очищенный HTML и предупреждает, если что-то будет удалено.

- **Сохранить для всех** — часть (темы или тест) записывается в базу и подменяет версию из сборки у всех пользователей при следующем открытии уровня. Приложение читает правку через REST, без загрузки SDK Firebase, с таймаутом 3 секунды; без сети, при ошибке или если правка некорректна, показывается версия из сборки. Кнопка активна, только если есть изменения и нет ошибок.
- **Отменить изменения** — черновик возвращается к тому, что сейчас видят пользователи.
- **Вернуть исходную версию** — из базы удаляется только эта часть правки; запись исчезает целиком, когда в ней не остаётся ни тем, ни теста. Если без этой части другая перестанет подходить (тест правки ссылается на темы, которых нет в сборке, или тест из сборки — на темы, которых нет в правке), удаляется вся запись; об этом предупреждает подтверждение.
- **Скачать JSON уровня** — файл уровня из сборки с текущими темами и тестом из редактора (обе части, в том числе несохранённые), чтобы положить его в репозиторий вместо старого.
- **Скачать индекс направлений** — тот файл индекса, где описано направление (`tracks.json` или `tracks-extra.json`), с `topicTitles` и `quizCount` уровня из редактора; остальное в файле не меняется. Положите его рядом с JSON уровня — тогда `content.spec.ts` останется зелёным. Если число тем изменилось, редактор напоминает: «Чтобы новая тема появилась на главной и в поиске, положите оба файла в репозиторий».

**Что обновляется само, а что — только после коммита.** Из правки в базе сразу (при следующем открытии уровня) берутся темы, тест, навигация по темам, кнопки «Дальше» / «К тесту» и прогресс на странице уровня. Роутер пропускает номера тем до 20 у известных уровней, а если в загруженном уровне такой темы нет, страница показывает «Тема не найдена» со ссылками на первую тему и на главную. Главная (карточки направлений и общий прогресс), пререндер, `sitemap.xml` и заголовки страниц для поисковиков берутся из индекса и файлов уровней в репозитории: новая тема появится там только после коммита обоих скачанных файлов и пересборки. До этого страница новой темы получает `noindex`.

**SEO.** Пререндер ([build/prerender.ts](build/prerender.ts)) строит статические страницы из файлов репозитория, а не из базы, поэтому поисковики видят правку только после того, как скачанные JSON уровня и индекс направлений закоммичены и сайт пересобран. В приложении правка из базы видна сразу; заголовки тем в навигации уровня берутся из загруженного уровня (до загрузки — из индекса).

Права выдаются вручную: в Firebase Console → Realtime Database добавьте запись `interviewPrep/admins/<uid> = true`. Свой uid редактор покажет после входа. Писать в `interviewPrep/content` правила базы разрешают только администраторам. Вход общий с синхронизацией прогресса: войдя в редактор, вы включаете синхронизацию и для своего аккаунта. Пререндер и поисковики админку не видят: у неё `noindex`, в `sitemap.xml` её нет.

### Статистика

**Сбор.** Посещения считает Google Analytics 4 через Firebase Analytics (`VITE_FIREBASE_MEASUREMENT_ID`). SDK аналитики загружается только после согласия посетителя в баннере внизу страницы; до этого cookies не ставятся. Выбор хранится в `localStorage`, изменить его можно ссылкой «Cookies» в подвале. Просмотр страницы отправляется после каждого перехода роутера ([src/app/seo](src/app/seo/index.ts)), админка не считается. Кроме просмотров приложение отправляет события `quiz_complete` (уровень и результат), `sign_up`, `login` и `feedback_sent` (тип замечания).

**Отчёт в админке.** Вкладка «Статистика» на `/admin` показывает пользователей, сессии, просмотры, вовлечённость и среднюю сессию с изменением к прошлому периоду, график по дням, популярные страницы, источники трафика, SEO (поисковые системы и страницы входа из поиска), устройства, страны и события. Данные берутся из Google Analytics Data API напрямую из браузера: администратор входит в Google с доступом только на чтение, токен живёт в памяти вкладки около часа.

Настройка (один раз):

1. **Google Analytics → Admin → Data streams → веб-поток → Enhanced measurement** — выключите «Page changes based on browser history events», иначе просмотры будут считаться дважды: приложение отправляет их само.
2. **Google Analytics → Admin → Property details** — скопируйте числовой Property ID в `VITE_GA_PROPERTY_ID`.
3. **Google Cloud Console** (проект Firebase) → **APIs & Services → Library** — включите **Google Analytics Data API**.
4. **APIs & Services → OAuth consent screen** — тип External, режим Testing; добавьте scope `.../auth/analytics.readonly` и свой Google-аккаунт в **Test users**.
5. **APIs & Services → Credentials → Create credentials → OAuth client ID** — тип Web application, **Authorized JavaScript origins**: `http://localhost:5173` и `https://leaderdsn.github.io`. Client ID — в `VITE_GOOGLE_OAUTH_CLIENT_ID`.
6. Те же три переменные (`VITE_FIREBASE_MEASUREMENT_ID`, `VITE_GA_PROPERTY_ID`, `VITE_GOOGLE_OAUTH_CLIENT_ID`) добавьте в секреты GitHub Actions.

Все три значения публичные: данные GA видит только тот, у кого есть доступ к ресурсу в Google Analytics.

### Обратная связь

Пользователи сообщают об ошибках в контенте и предлагают улучшения прямо из приложения.

**Точки входа** (форма одна, тип заранее выбран по месту):

| Где | Как | Тип по умолчанию | Контекст |
|---|---|---|---|
| Тема | выделить текст и нажать **Ctrl+Enter** (⌘+Enter) или плавающую кнопку «Сообщить об ошибке» у выделения | Опечатка | уровень, номер и заголовок темы, цитата (до 300 символов) |
| Конец темы | «Нашли ошибку или есть замечание?» | Неточность или ошибка | уровень, номер и заголовок темы |
| Тест после проверки | «Ошибка в вопросе» у каждого вопроса | Ошибка в тесте | уровень, индекс вопроса в тесте уровня, текст вопроса |
| Подвал | «Обратная связь» | Предложение | страница |

Кнопка у выделения появляется только для выделения внутри статьи темы, ставится под ним (сверху у телефонов своё меню «Копировать»), не снимает выделение при нажатии и доступна с клавиатуры. В форме: тип (Опечатка, Неточность или ошибка, Устарело, Ошибка в тесте, Предложение), комментарий (5–2000 символов), необязательная почта для ответа (подставляется у вошедших) и контекст только для чтения. Форма с `Dialog` — отдельный чанк, он и SDK Firebase грузятся, только когда форму открыли; без настроек Firebase точки входа скрыты. После отправки — событие аналитики `feedback_sent` с типом.

**Хранение.** `interviewPrep/feedback/<pushId>`:

```ts
{ kind: 'typo' | 'inaccuracy' | 'outdated' | 'quiz' | 'suggestion', text, email?, page, levelId?, step?: number | 'quiz',
  topicTitle?, questionIndex?, questionText?, quote?, appVersion, createdAt /* время сервера */, uid, status: 'new', adminNote? }
```

**Защита от спама без сервера.** Писать в базу может только вошедший аккаунт, поэтому, если никто не вошёл, при отправке выполняется анонимный вход Firebase (`signInAnonymously`). Анонимный аккаунт входом не считается: `useSessionStore().user` для него остаётся `null`, поэтому шапка, синхронизация прогресса и проверка прав администратора его не видят, а флаг «входил раньше» не ставится (SDK не грузится на следующих визитах). Вход через Google или по почте потом просто заменяет анонимную сессию.

Замечание и отметка частоты пишутся одним многопутевым `update`:

```ts
{ 'interviewPrep/feedback/<id>': { …, createdAt: serverTimestamp() },
  'interviewPrep/feedbackLimits/<uid>': { at: serverTimestamp(), item: '<id>' } }
```

Правила ([database.rules.json](database.rules.json)):

- `feedbackLimits/<uid>` пишет только владелец, и только если `at === now` (время сервера) и прошлая отметка старше 30 секунд. Удалить или сдвинуть её назад нельзя.
- `feedback/<id>` создаётся (`!data.exists()`), только если в том же запросе отметка автора равна `now`, а `item` в ней — id именно этой записи. Отдельный запрос без отметки, запись чаще раза в 30 секунд и несколько записей одним запросом отклоняются.
- `.validate`: обязательные поля, типы и длины как в форме, `status === 'new'`, `uid === auth.uid`, `createdAt === now`, лишние поля и `adminNote` от автора запрещены.
- Администратор (`interviewPrep/admins/<uid> === true`) читает список, меняет `status` и `adminNote` и удаляет записи; автора и время изменить не может.
- Автор с настоящим (не анонимным) аккаунтом читает только свои записи запросом `orderByChild('uid').equalTo(uid)` — так работает список «Мои замечания» в окне аккаунта. Индексы: `uid`, `createdAt`.

Правила проверяет [rules.spec.ts](src/entities/feedback/config/rules.spec.ts): небольшой симулятор выполняет выражения из `database.rules.json` и прогоняет через них в том числе запись, которую собирает приложение. Ограничение: анонимный аккаунт можно пересоздать, очистив данные сайта, — правила замедляют спам, но не исключают его полностью. Если понадобится строже, включите Firebase App Check.

**Админка.** Вкладка «Отзывы» на `/admin` со счётчиком новых: список новыми сверху и фильтр по статусу (Новые, В работе, Исправлено, Отклонено, Все). В карточке — тип, текст, цитата, место, ссылка на страницу (в новой вкладке), дата, почта автора, если указана; статус, заметка администратора (автор её не видит), удаление с подтверждением на месте и «Открыть в редакторе»: вкладка «Контент» откроет нужный уровень и тему или прокрутит к вопросу теста. Если темы или вопроса с таким номером уже нет (тему удалили или переставили), редактор показывает предупреждение и остаётся на первой теме. Если в редакторе есть несохранённые правки другого уровня, переход не выполняется, чтобы их не потерять.

**Для автора.** В окне аккаунта (кнопка в шапке) у вошедших через Google или почту есть «Мои замечания» — последние замечания со статусами, список загружается при раскрытии. Замечания, отправленные до входа анонимно, к аккаунту не привязываются.

**Что включить в Firebase:**

1. **Authentication → Sign-in method → Anonymous** — включить.
2. **Realtime Database → Rules** — заново вставить [database.rules.json](database.rules.json) и опубликовать (в нём новые узлы `feedback` и `feedbackLimits` и индексы).

### SEO

Приложение — SPA, поэтому после `vite build` плагин [build/prerender.ts](build/prerender.ts) создаёт статический HTML для каждой страницы: главной, каждой темы и каждого теста (`dist/level/<уровень>/<шаг>/index.html`). В HTML уже есть текст темы, свои `title` и `description`, `canonical`, Open Graph и JSON-LD (`BreadcrumbList`, `LearningResource`, `WebSite`), так что поисковики видят содержимое без выполнения JS. Приложение монтируется через `createApp` и просто заменяет статический HTML, гидратации нет.

- Заголовки и описания строит [src/app/seo/meta.ts](src/app/seo/meta.ts). Тот же модуль использует роутер: после каждого перехода [src/app/seo](src/app/seo/index.ts) обновляет `<head>`. Служебным страницам (админка, 404) ставится `noindex`, их заголовок задаётся в `meta.title` маршрута.
- Плагин также пишет `sitemap.xml`, `robots.txt` и `404.html` (GitHub Pages отдаёт его на неизвестные адреса, дальше страницу открывает роутер).
- Канонические адреса заканчиваются слэшем: GitHub Pages отдаёт пререндеренные страницы как папки и перенаправляет `/level/vue-junior/1` на `/level/vue-junior/1/`.
- На адресе вида `<user>.github.io/<repo>` поисковики не читают `robots.txt` из подпапки, поэтому `sitemap.xml` нужно отправить вручную в Google Search Console и Яндекс Вебмастер. С собственным доменом `robots.txt` заработает сам; не забудьте поменять `VITE_SITE_URL` и `base` в [vite.config.ts](vite.config.ts).
- Новые направления и темы попадают в пререндер и `sitemap.xml` автоматически. Темы, добавленные только правкой в базе, — после коммита скачанных JSON уровня и индекса направлений; до этого их страницы получают `noindex`.
